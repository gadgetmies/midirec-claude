## 2. Build the clockSender core

- [x] 2.1 Create `src/midi/clockSender.ts` exporting `emitClock(outs, timestamp)`, `emitStart(outs)`, `emitContinue(outs)`, `emitStop(outs)` — each iterates `outs` and calls `MIDIOutput.send([byte], timestamp)`. Each function filters out disconnected ports silently (try/catch around the call so a stale reference does not throw).
- [x] 2.2 Add `emitSongPositionPointer(outs, sppBeats)` to the same module; computes `[0xF2, sppBeats & 0x7F, (sppBeats >>> 7) & 0x7F]` with `sppBeats` clamped to `0..16383`. Adds `emitNoteOn`, `emitNoteOff`, `emitCC` helpers for the Grid Alignment trigger; status byte computed via `(0x90|0x80|0xB0) | (channel - 1)`.
- [x] 2.3 Add `emitSyncBundle(outs, playheadTicks, tpq)` that calls `emitStop`, `emitSongPositionPointer`, and `emitStart`-or-`emitContinue` (based on `playheadTicks === 0`) in a tight synchronous loop with no `await` or microtask boundary between them — preserves byte order per output.
- [x] 2.4 Add `createInternalScheduler({ getBpm, getOutputs, onPulse })` returning `{ start(), stop(), reset() }`. Use `performance.now()` + 25 ms lookahead, next batch via `setTimeout(..., 12 ms)`. The scheduler computes the next due `0xF8` timestamp from current bpm at each tick; bpm changes take effect on the next batch (no in-flight cancellation).
- [x] 2.5 Add unit tests in `src/midi/clockSender.test.ts`: covers (a) `emitClock` sends `[0xF8]` to each output exactly once with the given timestamp, (b) scheduler emits ~48 pulses/sec at 120 BPM over 1000 ms (±2 tolerance, using fake timers), (c) `stop()` halts further emissions within 50 ms, (d) bpm change between batches is honored, (e) a disconnected output is silently skipped, (f) `emitSongPositionPointer(out, 32)` sends `[0xF2, 0x20, 0x00]`, (g) `emitSongPositionPointer(out, 30000)` clamps to `[0xF2, 0x7F, 0x7F]`, (h) `emitSyncBundle` emits the three bytes in correct order to each connected output with no microtask boundary (verified by checking call order on a synchronous mock), (i) `emitNoteOn(out, ch=2, note=60, vel=100)` sends `[0x91, 60, 100]`, (j) `emitCC(out, ch=1, cc=20, val=64)` sends `[0xB0, 20, 64]`.
- [x] 2.6 Run `npm run typecheck` and `npm run test -- clockSender`.

## 3. Build MidiClockSendProvider

- [x] 3.1 Create `src/midi/MidiClockSendProvider.tsx` exporting a default provider plus `useMidiClockSend()`. State is a single `useReducer` over `{ enabled, selectedOutputIds: Set<string>, txPulse }`. Reset to defaults on mount; do not persist.
- [x] 3.2 Implement actions: `setEnabled(b)` (clamp to `false` when `useMidiOutputs().status !== 'granted'`), `toggleOutput(id)` (immutable Set update), `setSelectedOutputs(ids)` (replace set).
- [x] 3.3 Implement the internal-clock effect: when `enabled === true` and `clockSource === 'internal'`, instantiate the scheduler with `getBpm = () => transport.bpm`, `getOutputs = () => outputs.filter(o => selectedOutputIds.has(o.id))`, `onPulse = () => bumpTxPulse()`. Tear down on any of those deps changing or on disable.
- [x] 3.4 Implement the external-relay effect: when `enabled === true` and `clockSource === 'external-clock'`, register `useMidiClock().onPulse((ts) => { emitClock(activeOuts, 0); bumpTxPulse(); })`. Unsubscribe on dep change.
- [x] 3.5 Implement transport-message effect: track previous `mode` and `timecodeMs` via refs; on mode transitions emit Start (idle → play, `timecodeMs === 0`), Continue (idle → play, `timecodeMs > 0`), or Stop (play → idle). When `setEnabled(true)` is called with `mode === 'play'`, emit one Start or Continue per timecode (this can live in `setEnabled` itself).
- [x] 3.6 Implement `bumpTxPulse()` rAF-coalesced: use a ref'd "pending bump" flag; if not pending, `requestAnimationFrame(() => { dispatch({ type: 'TX_PULSE' }); pendingRef.current = false; })`. Coalesces multi-pulse batches at >60 Hz.
- [x] 3.7 Implement the `sync()` action: when `enabled === true` and at least one selected connected output, compute `playheadTicks` and `tpq`, then call `emitSyncBundle(connectedSelectedOuts, playheadTicks, tpq)`. The internal scheduler SHALL NOT pause; `txPulse` SHALL NOT advance from this call. No-op when disabled or no outputs.
- [x] 3.8 Add `gridAlignment` state to the reducer: `{ enabled, outputId, message, boundary, phraseBars }` with the defaults from the spec. Add `setGridAlignment(patch)` action that merges and clamps (channel 1..16, note/cc/vel/val 0..127, phraseBars 1..32). Add `fireGridAlignment()` action that resolves the output and emits Note On + delayed Note Off (50 ms via `setTimeout`) OR a single CC.
- [x] 3.9 Implement automatic Grid Alignment firing:
  - Internal mode: a `useEffect` watching `useTransport().playheadTicks`; hold `prevTicks` in a ref; on each render compute current boundary tick from `sig`/`boundary`/`phraseBars`; fire if `prevTicks < boundary <= curr`.
  - External mode: subscribe via `useMidiClock().onPulse(...)`; maintain a pulse counter; fire when divisible by `24 * beatsPerBar` (bar) or `24 * beatsPerBar * phraseBars` (phrase). Reset counter to 0 on accepted `0xFA` Start (add a small `onStart` hook to `MidiClockProvider` or watch a counter field).
  - In both modes, only fire when `gridAlignment.enabled === true`, `outputId` resolves to a connected output, and `useTransport().mode === 'play'`.
- [x] 3.10 Add `txPulseByOutputId: ReadonlyMap<string, number>` to the provider state so per-port LEDs in the Inspector can blink independently. Bump per-port concurrently with `txPulse` on every clock batch, rAF-coalesced.
- [x] 3.11 Add unit tests in `src/midi/MidiClockSendProvider.test.tsx`: state defaults, `setEnabled` clamp under no-grant, hotplug-retention of `selectedOutputIds`, Start/Continue/Stop on mode transitions, no transport message on record-mode entry/exit, `txPulse` advances at most once per rAF, `sync()` no-op when disabled, `sync()` emits the bundle when armed, `sync()` does not pause scheduler, `gridAlignment` defaults, `setGridAlignment` clamping, automatic bar-boundary fire in internal mode, automatic phrase-boundary fire in external mode, manual `fireGridAlignment` works when auto disabled, manual fire is no-op when `outputId === null`, pulse counter resets on incoming Start.
- [x] 3.12 Mount `<MidiClockSendProvider>` in `src/App.tsx` inside `<MidiRuntimeProvider>`, `<TransportProvider>`, and `<MidiClockProvider>`, before `<TimelineStorageProvider>`.
- [x] 3.13 Run `npm run typecheck` and `npm run test -- MidiClockSendProvider`.
